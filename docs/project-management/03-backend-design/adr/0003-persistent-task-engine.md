# ADR 0003：采用持久 Task Engine

- **日期**：2026-07-11
- **状态**：Accepted

## 背景

AI/诊断任务包含多步骤、取消、崩溃和重启恢复，内存协程不能提供确定状态。

## 决策

Task 和 TaskStep 状态持久化；每次转换受状态表约束并写事务。

## 备选方案

- 维持临时实现并后补边界。
- 使用另一套桌面/执行架构。
- 将能力交给云端服务。

以上方案因安全边界、单人维护或本地优先目标不符合而未选择。

## 影响

需要恢复和幂等设计；换来未知状态为零和可审计执行。

## 验证

通过对应 Backlog、架构测试和 Beta 门禁验证；若事实推翻决策，创建新 ADR supersede 本记录。
